THUYẾT MINH KIẾN TRÚC HỆ THỐNG KMS

Giải thích chi tiết 6 lớp cấu phần, luồng xử lý RAG & Obsidian và các điểm hiệu chỉnh trên sơ đồ ERP

Tầng 1: Access Layer (Lớp người dùng)
3 Components
Quản trị viên (Admin)
Quản lý cấu hình AI hệ thống và theo dõi nhật ký hoạt động.
Giáo viên (Teacher)
Tải lên và quản lý tài liệu giáo án riêng / đề xuất dùng chung.
Người dùng (User)
Đọc tài liệu công khai và trò chuyện hỏi đáp ngữ nghĩa với AI.
Tầng 2: Presentation Layer (Giao diện React)
6 Components
Admin Config Dashboard
Giao diện điều khiển cấu hình tham số AI của Admin.
Chatbot Workspace Widget
Widget nổi hỗ trợ người dùng chat RAG với AI.
Dashboard & Library View
Lưới thư viện giáo án công cộng và thư mục cá nhân.
Symmetrical Mindmap Canvas
Bản đồ tư duy đối xứng mục lục bài dạy tương tác.
Knowledge Graph Canvas 2D
Đồ thị mạng lưới 2D liên kết chéo giáo án & khái niệm.
Premium WikiNotes Split-Pane
Khung đọc WikiNotes và liên kết chéo WikiLinks Obsidian.
Tầng 3: Security & Integration Layer (Bảo mật & Phân tuyến)
3 Components
Axios Request Interceptor
Tự động nhúng JWT Token xác thực vào Header HTTP.
Keycloak / Local Auth Provider
Đăng nhập một lần SSO Keycloak hoặc xác thực CSDL cục bộ.
API Gateways & Routers
Hệ thống phân luồng API Django REST Framework.
Tầng 4: Business Logic Layer (Xử lý nghiệp vụ Django)
4 Components
User & Account Controller
Xử lý tài khoản và đồng bộ chi tiết người dùng Keycloak.
Vault Synchronization Engine
Ghi tệp tin Markdown (.md) và dọn dẹp Obsidian Vault rác.
Document Lifecycle Manager
Quản lý vòng đời giáo án, xếp hạng và lịch sử chỉnh sửa.
Pedagogical & Word Parser
Đọc cấu trúc file Word (.docx) trích xuất văn bản & metadata.
Tầng 5: AI Processing Layer (Tầng xử lý AI)
4 Components
Asynchronous Task Manager
Điều phối 5 Phase xử lý AI và đồng bộ chạy ngầm.
Graph RAG Retrieval Engine
Tìm kiếm ngữ nghĩa RAG kết hợp Vector DB và đồ thị tri thức.
LLM Inference Bridge
Cầu nối gọi phản hồi LLM (Local Qwen2.5 hoặc API GPT-4o).
Embedding Service
Sinh vector nhúng ngữ nghĩa (OpenAI / Ollama Local Embed).
Tầng 6: Data Storage Layer (Tầng Lưu Trữ)
2 Components
PostgreSQL DB (với pgvector)
CSDL quan hệ PostgreSQL tích hợp Extension pgvector.
Obsidian Vault Store
Kho lưu trữ tệp Markdown (.md) vật lý chuẩn Obsidian.
1
Upload giáo án Word từ Giao diện
Giao diện (Frontend)
Giáo viên click Tải lên giáo án trên Thư viện, chọn file Word (.docx) và nhấn Xác nhận.
Xử lý (Backend)
Axios Interceptor gắn Token JWT gửi file. Pedagogical Parser đọc cấu trúc XML thô của file Word.
2
Khởi chạy Task Manager ngầm (Phase 1-2: Cắt Chunks)
Giao diện (Frontend)
Giao diện nhận kết quả 200 OK và hiển thị vòng xoay tiến trình xử lý AI trên card bài học.
Xử lý (Backend)
Asynchronous Task Manager chạy ngầm chia văn bản bài dạy thành các Chunks (~500 ký tự) và ghi SQL lưu vào PostgreSQL.
3
Phase 3: Nhúng Vector và lưu CSDL
Giao diện (Frontend)
Trạng thái tiến trình AI hiển thị: "Đang sinh vector nhúng RAG..."
Xử lý (Backend)
Gọi Embedding Service nhúng các chunks văn bản thành vector. Thực hiện câu lệnh SQL ghi vector vào pgvector Extension.
4
Phase 4: LLM trích xuất Khái niệm cốt lõi
Giao diện (Frontend)
Trạng thái tiến trình AI hiển thị: "Đang bóc tách thực thể tri thức..."
Xử lý (Backend)
Gửi văn bản qua LLM Inference Bridge để trích xuất 8-12 khái niệm cốt lõi. Đồng thời sinh mô tả định nghĩa học thuật cho khái niệm.
5
Phase 5: Đồng bộ tệp Markdown vào Obsidian
Giao diện (Frontend)
Trạng thái hiển thị: "Hoàn thành xử lý!". Giáo án sẵn sàng hiển thị trên các Canvas bản đồ 3D/2D.
Xử lý (Backend)
Vault Synchronization Engine tạo các file ghi chú (.md) bài học và khái niệm có WikiLinks [[Liên kết]], ghi trực tiếp vào thư mục đĩa Obsidian Vault Store.
1
Đặt câu hỏi hỏi đáp với AI Chatbot
Giao diện (Frontend)
Người dùng mở Chatbot Widget, nhập câu hỏi (Ví dụ: "Protein là gì?") và bấm gửi.
Xử lý (Backend)
Gửi tin nhắn kèm JWT token qua API Gateway vào Document Lifecycle Manager.
2
So khớp Vector tương đồng câu hỏi
Giao diện (Frontend)
UI hiển thị màn hình bong bóng chat của người dùng và hiển thị vòng xoay "AI đang trả lời...".
Xử lý (Backend)
Graph RAG Engine gọi Embedding Service đổi câu hỏi thành vector. Chạy truy vấn tương đồng (Cosine) trên pgvector tìm các đoạn văn bản tương đồng nhất.
3
Dựng đồ thị con và đọc mô tả Khái niệm
Giao diện (Frontend)
Frontend chuẩn bị bộ khung hiển thị đồ thị mạng lưới tri thức RAG thu nhỏ ngay trong khung chat.
Xử lý (Backend)
Engine tìm quan hệ liên kết chéo trong PostgreSQL DB. Với mỗi nút khái niệm, nó đọc file .md trực tiếp trên Obsidian Vault để lấy chi tiết định nghĩa.
4
LLM sinh phản hồi và Stream kết quả lên UI
Giao diện (Frontend)
UI nhận luồng text streaming hiển thị chạy chữ thời gian thực kèm các Citation Badge trích nguồn và Mini Subgraph.
Xử lý (Backend)
Engine ghép (Chunk + Mối quan hệ + Định nghĩa khái niệm) vào Prompt và truyền qua LLM Inference Bridge nhờ mô hình sinh và stream câu trả lời về Client.
1
Hợp nhất pgvector Extension vào PostgreSQL DB
Tại sao sửa: Cách đã sửa:

[Lý do] Ở sơ đồ cũ, pgvector được vẽ như một xi lanh dữ liệu độc lập chạy song song với PostgreSQL DB. Về mặt bản chất, pgvector là một Extension được cài đặt trực tiếp vào trong nhân PostgreSQL DB, dùng chung một tiến trình và tệp tin lưu trữ.
[Cách sửa] Tôi đã gom khối `pgvector Extension` nằm gọn gàng bên trong khối `PostgreSQL DB` trong tệp sơ đồ để phản ánh chính xác 100% cấu trúc vật lý của cơ sở dữ liệu.

2
Sửa hướng mũi tên của Vault Synchronization Engine về Obsidian
Tại sao sửa: Cách đã sửa:

[Lý do] Sơ đồ cũ vẽ mũi tên từ `Vault Synchronization Engine` trỏ vào PostgreSQL DB với nhãn "Ghi tệp vật lý". Điều này sai nghiêm trọng vì PostgreSQL chỉ lưu trữ các bản ghi quan hệ, còn tệp ghi chú vật lý Markdown `.md` của Obsidian phải được ghi xuống ổ đĩa thư mục Obsidian Vault.
[Cách sửa] Chuyển hướng mũi tên này trỏ trực tiếp sang `Obsidian Vault Store` với nhãn *"Ghi tệp tin vật lý / Dọn dẹp"*.

3
Xóa đường kết nối rác từ Task Manager trực tiếp xuống Obsidian
Tại sao sửa: Cách đã sửa:

[Lý do] Asynchronous Task Manager là lớp xử lý AI chạy ngầm. Nó không trực tiếp can thiệp I/O ghi file vật lý mà phải ủy quyền cho `Vault Synchronization Engine` ở tầng Logic (qua đường *"Phase 5: Đồng bộ ghi tệp"*). Đường kết nối trực tiếp xuống Obsidian là bị thừa và vi phạm quy chuẩn phân lớp.
[Cách sửa] Xóa bỏ hoàn toàn đường nối này khỏi sơ đồ.

4
Xóa đường kết nối rác từ Embedding Service sang Obsidian
Tại sao sửa: Cách đã sửa:

[Lý do] Embedding Service chỉ là thư viện tính toán sinh vector float, nó không lưu trữ vector hay đọc/ghi file trên Obsidian. Đường nối này gây hiểu nhầm nghiêm trọng về chức năng.
[Cách sửa] Xóa bỏ hoàn toàn đường nối này.

5
Đổi nhãn từ Vector Similarity Search thành Direct File I/O Read của Graph RAG trỏ vào Obsidian
Tại sao sửa: Cách đã sửa:

[Lý do] Obsidian Vault chứa các file tĩnh dạng Markdown, không có động cơ lưu hay chỉ mục vector để thực hiện tìm kiếm tương đồng vector. Khi Chatbot hoạt động, Graph RAG Engine mở tệp bằng lệnh Python I/O đọc trực tiếp nội dung văn bản khái niệm để lấy mô tả.
[Cách sửa] Đổi nhãn mũi tên này thành **`Direct File I/O Read`** (Đọc file trực tiếp).

6
Thêm kết nối "Sinh & Ghi Vector" từ Embedding Service trỏ vào pgvector Extension
Tại sao sửa: Cách đã sửa:

[Lý do] Ở sơ đồ cũ, pgvector Extension bị mồ côi (không có bất kỳ mũi tên nào kết nối do các luồng sai đã bị loại bỏ). Cần phải vẽ rõ luồng sinh và ghi vector nhúng của chunk tài liệu xuống CSDL lưu trữ.
[Cách sửa] Thêm mũi tên một chiều hướng xuống từ `Embedding Service` trỏ vào `pgvector Extension` với nhãn **`Sinh & Ghi Vector`**.

7
Thêm kết nối "Vector Similarity Search" từ Graph RAG Retrieval Engine trỏ vào pgvector Extension
Tại sao sửa: Cách đã sửa:

[Lý do] Bị thiếu luồng truy vấn đối chiếu khoảng cách tương đồng vector ngữ nghĩa của câu hỏi người dùng khi chat.
[Cách sửa] Thêm mũi tên một chiều hướng xuống từ `Graph RAG Retrieval Engine` trỏ vào `pgvector Extension` với nhãn **`Vector Similarity Search`**.

8
Chuẩn hóa tất cả các mũi tên CSDL thành một chiều hướng từ trên xuống dưới và đổi tên nhãn SQL Queries
Tại sao sửa: Cách đã sửa:

[Lý do] Trong sơ đồ cũ, các mũi tên nối CSDL bị vẽ ngược hoặc hai chiều, điều này sai nguyên lý kiến trúc (CSDL là thành phần bị động, không bao giờ chủ động gọi lên Controller). Đồng thời nhãn "SQL Queries" cũ gây hiểu lầm là chỉ đọc dữ liệu mà không có ghi ghi dữ liệu vào CSDL.
[Cách sửa] Tôi đã chuyển toàn bộ 7 đường kết nối trỏ xuống Data Storage Layer thành mũi tên 1 chiều hướng xuống dưới, đồng thời đổi tên nhãn "SQL Queries" thành **`SQL Queries (Đọc/Ghi)`** để làm rõ các hành động SELECT, INSERT, UPDATE, DELETE.
